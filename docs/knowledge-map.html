How to read this

Server. A multiplayer game needs a central program that every player connects to and that decides what is true in the shared world. AnarchyKenshi contains server logic inside its main DLL, but it can never run. The networking DLL that ships with it has all 192 server functions replaced by empty stubs. The mod even logs "this build has no server in it". So the server has to be written new.

Game mod (client). The part that runs inside each player's Kenshi. It hooks into Kenshi's own code: it intercepts functions like "move character" or "save game" and reports them to the server, or applies what the server says. To do that it needs to know where those functions live in the game's executable. That is the list of 795 addresses.

Spine. The mod's name for its sync layer. It keeps 48 areas of game state in step between players: traders, squads, injuries, machines, weather, factions and more. Each area has its own data format. The formats of all 48 are decoded (what the server sends, what a player's game asks for); for about half of them some server-side rules or field meanings are still open.

Measured vs. inferred. "Known" means the fact was read directly from the binary: message sizes, field order, addresses, byte patterns. What a field means is often an educated guess and is marked as such in the detailed notes.
