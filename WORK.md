# WORK

Goal: an own Kenshi multiplayer (own server + client mod) that works better than AnarchyKenshi and is fully under the user's control, without depending on another mod (RE_Kenshi); everything is extracted from the client DLLs first (the original server is not available).

- Route: own server and own client mod, AnarchyKenshi only a reference; plan in `docs/plan-first-playable.md`. M0 done. M0b done (own Ogre-plugin loader, own address table for 1.0.65 and 1.0.68, early DXGI fix, no KenshiLib; user runs with and without RE_Kenshi passed, probe answered on 1.0.68). M1 done (own pose read and logged; user's run passed, `docs/client.md` "Own pose (M1)"). M2 done (own protocol `docs/protocol-ours.md`, relay server `kp-server`, test bot `kp-bot`, tests pass; `net/`). Next: M3 (the game sends and receives poses: core DLL + network thread).
- M1 gaps: only one owned character tested (selection switching not seen); `destination` and `pathDestination` never differed (a long path around obstacles may show the difference); the first sample after a load can be half set up (destination 0/0/0, yaw not matching facing, `docs/client.md` "Own pose (M1)"): M3 must not send it.
- In-game cheat menu for the user (their testing tool while we build, e.g. "take damage, then try X"): heal, damage, knock out, spawn item, teleport, as a window or hotkeys in game. Build it on the new foundation (M0b), not on KenshiLib. Known probe bugs to avoid there (`docs/client.md`): weapon spawn fails, quantity > 1 also drops extra single items, teleport is lost while paused. The user's Kenshi still has KenshiPure installed with `-ProbeWrite`.
- M0 run: one first-chance access violation in `RE_Kenshi.dll+0x381e9` at game exit (likely handled); check whether the game exits cleanly with KenshiPure.
- Reference version is fixed at v0.133.1 (the repo copy). The mod updates almost daily (the Steam install was reportedly v0.136.1, protocol `0x88`, ABI `0x60`); later versions are not diffed or tracked unless the user asks.
- Host ABI (`AnarchyHost*` signatures from their call sites in AnarchyKenshi.dll): only needed if the route ever changes to reusing AnarchyKenshi's server code.
- Spine: layouts of all 48 topics are in `docs/findings/spine-topics.md` (open items per topic under "Open"). Before an own server relies on the digest: decode the exact row-hash combine `0x53d380` (a wrong one makes every client resync forever).
- Spine drafts in `tools/work/spine-notes/` (gitignored) can be deleted once nobody needs them; the condensed note replaces them.
- Runtime logs in `<Kenshi>\mods\AnarchyKenshi\` (`AnarchyKenshi*.log`, crash dumps; they contain other players' chat) could confirm the live build detection, scan result and installed hook count; the user allows reading them (not committing them), but `AnarchyKenshi-logins.txt` there likely holds credentials (never read or commit it).
- Without RE_Kenshi the first frame came after ~100 s instead of ~20 s (no shader cache); a loading-time fix of our own may be worth it later.
- Address layer gaps: `InventorySection::SectionItem::item` has no 1.0.68 proof (probe `inventory` off on 1.0.68; prove it via the loop in `InventorySection::hasItem`); `sites.mjs` cannot add `patch`/`callsite`/`data` rows yet and there is no code-cave allocator (needed for AK-style mid-function patches); callees of proven functions are not compared (call targets masked); unknown builds resolve no vslot rows.
- Step 6 of the loader plan (modern-compiler core behind a C interface): planned in `docs/plan-own-loader.md` "Core split"; build it at M3 with `net/proto` + `net/client` inside. `NetClient` is single-threaded: M3 runs it on the network thread only and passes poses through queues; the core needs an explicit start call (no thread start inside `DllMain`).
- M2 gaps: `scripts/setup-modern.ps1` only run on this PC (each part once from scratch; not on a clean PC or another Windows); the ENet-timeout leave (PlayerLeft reason 1) is not tested (needs ≥ 5 s silence); the server has no per-IP limit and no login (fine for LAN/VPN, not for a public server).
